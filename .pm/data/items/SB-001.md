Task 6's features/sim/ca_engine.gd has untyped lambda params and untyped 'for' iterators at lines ~130/133/138 (the weighted-top-3 selection): 'func(a, b):' and 'for t in top3'. Under the project's project.godot [debug] gdscript/warnings/untyped_declaration=2 (warning-as-ERROR), ca_engine.gd FAILS its strict reload compile.

At Task 6 this was latent: only test scripts referenced CAEngine, and that reference path did not trigger the strict reload. Task 8 makes autoload/sim.gd and autoload/world.gd statically depend on CAEngine (CAEngine.new(), CAEngine.PASSIVE_HOURS_PER_DECISION). Now every GUT-driven autoload reload prints:
  Parse Error: Parameter "a"/"b" has no static type (ca_engine.gd:130)
  Parse Error: Function "<anonymous lambda>()" has no static return type (ca_engine.gd:130)
  Parse Error: "for" iterator variable "t" has no static type (ca_engine.gd:133, :138)
  Compile Error: Failed to compile depended scripts (sim.gd:0, world.gd:0)

IMPACT: The official DoD command (-s addons/gut/gut_cmdln.gd -gdir=res://test/unit -gexit) still EXITS 0 with 97/97 passing and NO method-not-found, because the autoload singletons instantiate once from the valid --import compile at boot; the spew is on subsequent reload attempts. But it is brittle (autoloads can't cleanly reload) and noisy.

FIX (out of Task 8 scope — Task 8 forbids touching ca_engine.gd): add the 3 trivial type annotations in ca_engine.gd _select_weighted_top3:
  - sort_custom lambda: func(a: Dictionary, b: Dictionary) -> bool:
  - for t: Dictionary in top3:  (both loops)
Behavior-preserving; clears the strict-reload failure. A runtime-load() workaround in sim.gd was tried and made it WORSE (CAEngine still fails strict compile when loaded fresh in-process → 22 tests failed to run), so the static reference must stay and ca_engine.gd must be made lint-clean.
